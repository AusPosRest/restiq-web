Behind the scenes

How we make RESTIQ's demo videos

No screen recorder and no video editor: every click is a script, every cut is a command, and the voice is generated. Change a sentence, run one command, and you get a new video.

The result: RESTIQ's 2-minute demo, built entirely by the steps on this page.

01The pipeline

We made two videos this way: a 2-minute demo for restaurant owners (above), and a 16-minute end-to-end test for our team that walks through 11 scenarios, from onboarding a restaurant to the owner's reports, with a pass or fail verdict for each step.

1 · PREPAREA test restaurant and private logins
2 · RECORDA script drives the live app, with captions on screen
3 · SCRIPTJSON: which clips, card text and voice lines
4 · VOICEElevenLabs reads each line, saved for reuse
5 · ASSEMBLEffmpeg joins cards, clips and voice

Because each stage is a file and a command, anything can be redone on its own. A wording change only re-voices one line, and a screen change only re-records one scene.

02Tools

03A safe place to record

We record on the live RESTIQ site so the videos show the real product, but always inside a restaurant account in Test mode. In Test mode, payments are simulated, emails stay inside the platform, and the restaurant isn't counted in platform figures. No real restaurant's data ever appears on screen.

Logins are kept in a private file that only the owner of the computer can read. The scripts read it at run time, so passwords never appear in a script, a video or this page. Each script also saves what the next one needs (a signed-in session, a device code, an order number), so the scenes follow on from each other like one real day of service.

04Recording with Playwright

There is one short script per scene: onboarding, the menu, taking an order on the till, the kitchen screen, paying, QR ordering on a phone, the self-order kiosk and reports. Running one produces one MP4:

node 06-pos-order.mjs     # → 06-pos-signin-table-order.mp4

A few small helpers make the recordings look like a careful person is using the app:

HelperWhy
session()Opens Chromium at 1280×800 (or a phone-sized touch screen for the QR guest), turns on video recording and slows every action a little so viewers can follow it.
caption(page, text)Shows a dark caption bar at the bottom of the page. The captions are part of the page while it records, not added afterwards, so they always match what's on screen.
typeIn()Types one key at a time, so viewers see the typing.
ensure()Waits until the screen has actually appeared, and reloads if it didn't, the way a person would.
finish()Closes the browser and converts Playwright's WebM into an H.264 MP4.

The caption helper is just a few lines of DOM code:

export async function caption(page, text, hold = 1800) {
  await page.evaluate((t) => {
    let el = document.getElementById('__demo_caption')
    if (!el) {
      el = document.createElement('div')
      el.id = '__demo_caption'
      el.style.cssText = 'position:fixed;left:50%;bottom:18px;transform:translateX(-50%);' +
        'z-index:2147483647;padding:10px 18px;border-radius:10px;background:rgba(17,24,39,.88);' +
        'color:#fff;font:600 16px/1.35 system-ui;pointer-events:none'
      document.body.appendChild(el)
    }
    el.textContent = t
  }, text)
  await new Promise((r) => setTimeout(r, hold))   // time to read it
}
Bonus: a recording run doubles as an end-to-end test. Each script logs every failed request and page error, and saves a screenshot if a step fails. Our first full run found eight bugs, all of them now fixed.

05The script is data

All the words live in a JSON file, separate from the code. The demo video is a list of sections. Each one has an optional card, the clips to use (recording number, start second, end second) and one voice-over line:

{ "card": { "kind": "section", "kicker": "03", "title": "Take orders fast",
            "sub": "PIN sign-in, table map, one tap to the kitchen" },
  "card_secs": 2.5,
  "clips": [["06", 46.0, 61.5]],
  "vo": "On the till, staff sign in with their own PIN and tap a table to start an order." }

For the end-to-end test video, each voice line is pinned to the second its caption appears in the recording ([5.0, "Staff sign in…"]), so the voice explains exactly what's on screen.

One small trick: the voice lines spell RESTIQ as "Resteek" so it's pronounced right, while the cards and captions still read RESTIQ.

06Title cards

Cards are a single HTML page with a few layouts: title, statement, numbered section, closing call to action, and for the test video the step, the pass/fail result and the summary. A small Playwright script loads the page once per card at 1920×1080, takes a PNG, and warns CLIPPED if any text runs off the edge. Changing the design means editing CSS, not using a design tool.

07The voice

A small Python client sends each line to the ElevenLabs text-to-speech API (voice George, stability 0.5, similarity 0.75, style 0.2). Every result is saved under a hash of the voice, settings and text, so rebuilding only pays for lines that changed. Fixing one sentence costs one sentence. The API key is read from a private file at run time and never printed or saved anywhere else.

08Putting it together

The build script turns everything into 1920×1080, 25 fps H.264 and joins it with ffmpeg. A few details make it look edited by hand:

  • The voice never gets cut off. If a line runs longer than its pictures, the last frame is held (tpad=stop_mode=clone) until the line finishes.
  • No white flashes. Page loads flash white for a moment. Inverting the picture turns those flashes black, ffmpeg's blackdetect finds them, and they are cut out: 
    ffmpeg -i in.mp4 -vf "negate,blackdetect=d=0.08:pix_th=0.15:pic_th=0.9" -f null -
  • Voice in step with the captions. In the test video the recording is cut at each caption, so every line starts with its caption and they never drift apart.
  • Smooth and even. Short crossfades between sections, a fade in and out, and the voice loudness-normalised to −16 LUFS (loudnorm=I=-16:TP=-1.5:LRA=11), the usual level for online video.
python3 build.py demo      # the 2-minute demo
python3 build.py e2e       # the end-to-end test video

09Make your own video

A · Re-cut existing footage

About 10 minutes, no recording. Good for a 30-second social clip, a video about one feature, or a different message for one customer.

B · Record something new

For screens that aren't in the existing recordings, or after the app's design changes. Then build as in A.

A. Re-cut existing footage

  1. Copy an existing plan, for example cp example-pos-video.json kitchen-for-cafes.json.
  2. Watch the recordings and note the start and end seconds of the moments you want. The on-screen captions tell you what's happening.
  3. Write the sections: 
    { "sections": [
  { "card": { "kind": "title", "title": "RESTIQ", "sub": "A kitchen screen that keeps up" },
    "card_secs": 4.0, "clips": [],
    "vo": "Meet Resteek, the kitchen screen built for busy cafés." },
  { "card": { "kind": "section", "kicker": "01", "title": "Every order, instantly",
              "sub": "Tickets arrive the moment the till sends them" },
    "card_secs": 2.5, "clips": [["07", 5.0, 18.0], ["07", 24.0, 30.0]],
    "vo": "Orders land on the kitchen screen the second they're sent, with a timer on every ticket." },
  { "card": { "kind": "closing", "title": "RESTIQ", "sub": "Book a demo", "url": "dailypos.shop" },
    "card_secs": 6.0, "clips": [],
    "vo": "Resteek. Book a demo at daily pos dot shop." }
] }
  4. Build it: python3 build.py demo kitchen-for-cafes.json → kitchen-for-cafes.mp4. For each section the build prints how long the pictures and the voice are. If it says held 4.0s, the voice ran 4 seconds past the pictures, so add footage or shorten the line.
FieldMeaning
card.kindtitle, statement, section or closing. Leave out card to show clips only.
card_secsHow long the card shows: about 2.5 for a section, 4 to 6 for the title and closing.
clips["NN", start, end], where NN is the recording number. Several clips are joined with a crossfade.
voOne voice line per section. It starts 0.6 s in.
Writing voice lines: allow about 2.5 words per second (a 15-second clip fits about 35 words). Keep to one idea per section, use short sentences, and spell out anything the voice could misread ("daily pos dot shop"). A 2-minute video uses about 2,000 ElevenLabs characters, and unchanged lines are free.

B. Record something new

  1. Copy the recording template: cp _template.mjs 12-new-feature.mjs. It's a working script that signs in and records the owner's dashboard.
  2. Write the steps with the helpers above. Every button and field in RESTIQ has a data-testid, so a step is just: 
    await caption(page, 'Add a new dish to the menu')
await page.locator('[data-testid="menu-add-item"]').click()
await typeIn(page, '[data-testid="item-name-input"]', 'Masala Chai')
  3. Run node 12-new-feature.mjs. If a step fails, the script saves a screenshot and prints the errors.
  4. Use the new recording in your plan like any other: "clips": [["12", 3.0, 14.0]].

Variations

  • Different voice: pick one in the ElevenLabs Voice Library and set RESTIQ_VOICE_ID before building.
  • Another language: the multilingual model speaks Hindi, Tamil and many more. Write the voice lines in that language. For translated captions, record the scenes again.
  • Your own look: the cards are plain HTML and CSS.
  • Vertical video (Reels/Shorts): record at phone size, switch the build to 1080×1920 and add a vertical card layout.

10Lessons learned

  • Script it, don't screen-record it. A re-take is one command, and captions, timing and typing speed come out the same every time.
  • Keep the words in data and the voice in a cache. Changing a word takes seconds, not a re-record.
  • Pin each voice line to its caption, and hold frames rather than rushing. This is what keeps the narration in sync.
  • Plan for hiccups. Automatic reloads let recordings finish even when a page is slow, and the error log turns those hiccups into a bug list.
  • Record in a test account, and keep secrets in private files. They never go into scripts, videos or pages like this one.
